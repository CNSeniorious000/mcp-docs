## 验证

为了培养一个健壮的开发者生态系统，我们计划投资于：

- **参考客户端实现**：使用高质量的 AI 应用展示协议功能
- **合规性测试套件**：自动验证客户端、服务器和 SDK 是否正确实现了规范

这些工具将帮助开发者自信地实现 MCP，同时确保生态系统中的一致行为。

## 注册表

为了让 MCP 发挥其全部潜力，我们需要简化的方式来分发和发现 MCP 服务器。

我们计划开发一个 [**MCP 注册表"](https://github.com/orgs/modelcontextprotocol/discussions/159)，它将启用集中式服务器发现和元数据。这个注册表主要作为一个 API 层，第三方市场和发现服务可以在此基础上构建。

## 代理

随着 MCP 越来越多地成为代理工作流程的一部分，我们正在探索[改进](https://github.com/modelcontextprotocol/specification/discussions/111)，例如：

- **[代理图](https://github.com/modelcontextprotocol/specification/discussions/94)**：通过命名空间和图感知通信模式启用复杂的代理拓扑
- **交互式工作流程**：通过细粒度的权限控制、标准化的交互模式和[与最终用户直接通信](https://github.com/modelcontextprotocol/specification/issues/97)的方式，改善人机交互体验

## 多模态

在 MCP 中支持 AI 能力的全谱，包括：

- **其他模态**：视频和其他媒体类型
- **[流式传输](https://github.com/modelcontextprotocol/specification/issues/117)**：多部分、分块消息和双向通信，用于交互式体验

## 治理

我们正在实施优先考虑以下方面的治理结构：

- **社区主导的开发**：培养一个协作的生态系统，让社区成员和 AI 开发者都能参与 MCP 的发展，确保其服务于多样化的应用和用例
- **透明的标准化**：建立明确的流程以贡献规范，同时探索通过行业机构进行正式标准化
